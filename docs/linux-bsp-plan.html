24 周怎么填满 1536 小时

纯 BSP 的内容量只有 850–1000 小时，剩下的 500 小时不能靠拖

上一版把周期压到 16 周，就是为了躲这个问题：内容塞不进 24 周，多出来的时间一定会变成看视频、抄代码、重装系统。你要 24 周，那就必须真的再加 500 小时的内容，而不是把同样的东西讲慢一点。

加的地方有三处，全部可验收：① 主线加厚——Yocto 从半周扩成整周，外设从 3 类扩到 8 类，驱动多加一层子系统驱动；② 加深度支线（每周约 4 项，共约 101 h）：从「读源码」升级到「子系统源码 + 性能 + 稳定性工程」；③ 加保底支线（每周约 3 项，共约 71 h）：嵌入式应用、MCU/RTOS、自动化测试，这三类岗位的量比 BSP 大得多。

代价仍然要说：64 h/周 × 168 天是职业运动员级负荷。第 6–8 周、第 13 周、第 19 周是三个已知的崩点，页面里都标了降载方案。如果你还在上班，这个计划物理上不成立——末尾有在职档。

三条腿：主线、深度、保底

每天 4 项主线 + 1 项支线。支线标「深」或「保」，一天只做一项，不许两样都碰。

主线 · MAIN

BSP 全链路

C 与工程能力 → 硬件与仪器 → 交叉编译 / U-Boot / 内核 / dts / rootfs → 驱动（字符·并发·中断·platform·总线·子系统）→ 八类外设 → 调试与性能 → 项目交付。

每天 4 项 · 约 1096 h · 决定你能不能干这行

深度 · DEEP

源码与系统认知

设备模型与 probe 调用链、内存管理、调度器、中断子系统、VFS、网络栈、ftrace/perf/eBPF、kgdb/JTAG、KASAN、PREEMPT_RT。这部分决定你三年后还在不在写驱动。

每周约 4 项 · 约 101 h · 决定薪资档位

保底 · BACKUP

三个可替代出口

嵌入式应用（C++/Qt/socket/MQTT/modbus）、MCU 与 RTOS（FreeRTOS/RT-Thread/CAN/OTA）、自动化测试（Python/pytest/HIL）。这三个方向的岗位数量是 BSP 的 3–5 倍。

每周约 3 项 · 约 71 h · 找不到 BSP 时的第二条路

六条出口：这份计划能投哪些岗

走完 24 周，你手上有四份可展示的东西：BSP 原型、应用层 Demo、测试框架、一份性能报告。它们对应六类岗位。

Linux BSP / 驱动工程师 主目标

W7–20 的全部主线，W21–24 的原型。这是计划的核心，也是唯一需要你讲得清上电到 shell的岗位。

关键词：U-Boot / dts / platform driver / I2C / 内核裁剪 · 一线 12–20K（1–3 年）

嵌入式应用（Linux C/C++）岗位最多

W1–4 的 C 底子 + 保底支线的 C++/socket/Qt，W24 交一个带界面的应用 Demo。不需要碰内核也能干活，岗位量是 BSP 的数倍。

关键词：C++11 / 多线程 / socket / Qt / MQTT / modbus · 一线 10–18K

测试开发 / HIL 自动化 门槛最低

W19–20 的调试能力 + 保底支线的 pytest/HIL 框架，能自己搭一套「串口控板子跑用例」的环境。这类岗最愿意要转行的，因为逻辑和耐心比年限重要。

关键词：Python / pytest / 自动化框架 / 串口 / CI · 一线 10–16K

MCU 固件（工业 / 车载 ECU）

保底支线的 FreeRTOS/RT-Thread + W17 的 CAN 总线，加上 W5 的硬件底子。工业控制器、BMS、电机驱动大量缺人，对学历要求比 BSP 松。

关键词：FreeRTOS / CAN / Modbus / 低功耗 / bootloader · 一线 10–18K

Android 系统层（车载座舱）

不是主线，是选修包：W21–24 可以把项目期切到 AOSP 编译 + HAL + binder。前提是你会 Java 或 Kotlin，且目标城市是上海、广州、深圳。

关键词：AOSP / HAL / binder / SELinux / 座舱 · 一线 15–25K，但门槛也高一档

FAE / 技术支持 兜底

W1–24 全部基础 + 你的表达与文档能力（每周一篇公开笔记就是训练）。出差多、技术深度浅，但入门最快，且能先进芯片厂或板厂，再内部转岗。

关键词：方案选型 / 客户支持 / 调试 / 文档 · 8–14K + 出差补贴

保底不是「学一半换方向」，是「同一段时间产出两种证据」

看 W15 的例子：主线做 IIO 驱动读传感器，保底支线做 Qt 界面把这个数据画出来。同一件事，两个视角，两份可展示物。面试 BSP 岗你讲内核那一侧，面试应用岗你讲界面那一侧。这才是保底该有的做法——不是分身学两套，是让一份工作产出两种证明。

真正危险的做法是：一边学 BSP 一边学 Java 后端。那两条线毫无交集，最后两条都半途而废。

两块板的分工

不要同时开工。两套 BSP 目录、两套启动流程，会把你绕晕。

阶段用哪块为什么是它
W1–4都不用在 PC 上把 C、Makefile、gdb、git 打穿。这时候碰板子只会分散注意力，板子也解决不了你的语法问题。
W5–6i.MX6ULL只用来量电压、抓波形、点灯。硬件阶段用最慢的板子，因为你量的是电，不是算力。
W7–9i.MX6ULL慢、外设少、手册规范。出错时变量少，容易定位。NXP 的 Reference Manual 结构清晰，打地基就该用变量最少的板子。
W10RK3568换板复现周。同样的流程在另一套 SDK 上重走一遍——这一步能拆穿「你到底会不会」和「你只会抄这一家的教程」。
W11–15i.MX6ULL驱动阶段回简单板子。中断、并发、platform、I2C 这些概念，在单核 A7 上出问题最好查。
W16–20RK3568外设广度靠它。千兆网口、MIPI DSI、CAN、USB3、PCIe，i.MX6ULL 都没有。简历上要写的八类外设，这里才凑得齐。
W21–24RK3568项目板。四核 A55 跑得动带界面的原型，接口多，而且它在工业网关、商显、车载后装真的在用。

三条必须提前知道

1｜韦东山那套视频是字典，不是连续剧。卡住了就去搜「那一节的第几分钟」，不要从第 1 期第 1 集顺序追完。追完你会以为自己会了，然后手是生的——讲得太清楚恰恰是这类课程最大的陷阱。

2｜RK3568 别提前玩。Rockchip 的 SDK 封装极厚，一条 ./build.sh 把所有东西都给你编出来，你会「会用但不懂」。等 W10 有能力拆开看的时候再用；提前上手会养成只会跑脚本的习惯，面试一问就穿。

3｜i.MX6ULL 的源码包亲手整理一遍。整理成 board/ boot/ kernel/ rootfs/ tools/ 的结构。这件事本身就是 BSP 的日常，也是你简历里「我懂工程组织」的证据。

八条铁律

违反任何一条，这个计划就不成立。全职冲刺没有冗余度。

每天必须有一次 commit。没有提交记录的那天，按 0 分计，哪怕只改了一个注释。
每天第一件事是回看昨天的笔记，不是打开新内容。15 分钟，不做这步不进主任务。
看视频不超过 30 分钟/天。8 小时里 7 小时必须是自己在写、在调、在读源码。
手机放在另一个房间。8 小时深度工作不是「在线 8 小时」，被消息切碎的时间不算工时。
每个 bug 必须落成笔记：现象 → 假设 → 验证 → 根因。四项缺一，等于没修过。
卡住超过 2 小时就跳过，记进待办，周日 21:00 统一处理。全职最容易死在「非要今晚搞明白」上。
每周日 23:00 前发一篇公开笔记，300 字也算。24 周要攒下 24 篇，这是你唯一的对外证据。
每两周做一次破坏性测试：故意删一把锁、改错一个地址、制造越界，看系统怎么崩。你对系统的理解深浅，全在这个动作里。

开发板你已经有了，只剩仪器。这一节只说不该买错的地方。

物品规格预算说明
逻辑分析仪8 通道 24MHz，兼容 Saleae50–90抓 I2C / SPI / UART / CAN 够用。认准能跑 Saleae Logic 2 的，杂牌上位机软件会让你用两次就放弃。
示波器 重点100MHz 带宽 · 双通道 · 1GSa/s1500–2600100MHz 是底线，不要买 50MHz。50MHz 看不了 RGMII、MIPI，等于白买；双通道才能同时看时钟和数据。
无源探头10:1，×2 根随机器多数标配两根。再买一根备用不亏，探头是最容易摔坏的耗材。

万用表入门数字款，带通断蜂鸣60–100测供电、查断线。蜂鸣档比看数字快十倍。

面试会问的十二个问题

前八个是 BSP 岗必问；后四个是保底岗（应用 / 测试 / MCU）的常见问法。答不出来就回补对应的周。

从按下电源到 shell 出现，依次发生了什么？
dts 是怎么被解析的，probe 在什么时机被调用？
中断上半部和下半部的区别，什么时候必须用工作队列？
自旋锁里能睡眠吗，为什么？互斥量能在中断里用吗？
copy_to_user 为什么不能用 memcpy 代替？
内核 panic 了，你从哪几行开始看？
板子启动要 8 秒，你怎么把它压到 4 秒？
讲一个你调了三天以上的 bug，根因是什么？
一个进程 CPU 占满，你怎么定位到是哪一行代码？
你的测试框架怎么判断「板子挂了」而不是「用例失败」？
RTOS 的任务切换和 Linux 的线程切换差在哪？
为什么选这个方向？如果让你做应用层，你愿意吗？

全职冲刺的五个陷阱

1｜用「在线时长」替代「深度时长」。8 小时里如果有 3 小时在刷消息、看视频、重装系统，那实际只有 5 小时。全职最大的敌人不是难度，是时间看起来很多。

2｜三个崩点：第 6–8 周、第 13 周、第 19 周。第 6 周是新鲜感耗尽 + 驱动开始难；第 13 周是 platform 驱动卡住 + 体力见底；第 19 周是性能和稳定性阶段，抽象、看不到进展。对策只有一个——那几天把任务量减半，但绝不中断。断一天，接回来的成本是一周。

3｜把教程当天书读。看 10 分钟，关掉，自己敲，卡住了再回去看那一段。这是唯一有效的用法。

4｜跳过手搓 Buildroot / Yocto。只会在厂商镜像上改驱动，面试一问「rootfs 怎么来的」就露馅。W9 那一周不要跳。

5｜支线越做越重。支线每天只有 50 分钟，它的作用是「铺第二条路」，不是「再学一个专业」。如果某天支线吃了两个小时，那天主线一定是欠账了。

如果你还在上班

80% 的人会在这里自我欺骗

工作日 8 小时意味着白天完全空出来。如果你现在有工作，这个计划不可能执行——不是意志力问题，是物理上不存在那 8 小时。

在职档：工作日 1.5 h（21:00–22:30）+ 周末 9 h × 2 = 25.5 h/周，周期拉到 40 周。删掉支线里的保底部分（只留深度），主线不删。

半职档：工作日 4 h + 周末 10 h = 40 h/周，周期 32 周。保留深度支线，砍掉一半保底支线。这个档位是多数人能坚持的上限。

宁可拉长，不要断。断了就再也接不上——这是所有自学计划最常见的死法，而且它从来不是因为太难，是因为计划表本身不现实。
